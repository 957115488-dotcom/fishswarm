# 00. MVP 开发范围

## 1. MVP 定义

鱼群 MVP 的目标是开发一个“多 Agent 协同办公工厂底座”的可运行版本。

它不是最终的企业级平台，也不是某个单一业务领域的完整交付系统。MVP 要证明用户可以把 Agent 当成员工配置进工厂，并让工厂围绕项目目标完成组队、拆解、执行、评审和产物沉淀。

第一版交付形态应是桌面应用。用户应该可以双击打开鱼群，在一个窗口里看到所有 Agent 的工作情况。

## 2. MVP 必须覆盖的主流程

### 2.0 启动桌面应用

用户双击鱼群应用图标。

系统需要：

1. 打开桌面窗口。
2. 自动启动本地 App Server。
3. 自动初始化本地 SQLite 数据库。
4. 打开 Agent Operations Dashboard。
5. 展示所有 Agent 的状态、任务、阻塞和待确认事项。

### 2.1 创建工厂

用户创建一个 Factory，并定义：

1. 工厂名称。
2. 工厂描述。
3. 适用项目类型。
4. 默认流程阶段。
5. 默认质量门禁。

### 2.2 Agent 员工入职

用户创建 AgentWorker，并配置：

1. 姓名。
2. 岗位。
3. 核心使命。
4. 职责。
5. 能力标签。
6. 行为约束。
7. 工具权限。
8. 输入 schema。
9. 输出 schema。
10. 评审标准。
11. 交接规则。

### 2.3 组建工厂团队

用户把 AgentWorker 加入 Factory，形成默认组织结构。

一个 Factory 可以包含：

1. 管理 Agent。
2. 执行 Agent。
3. 评审 Agent。

### 2.4 派发项目

用户基于某个 Factory 创建 Project。

项目需要包含：

1. 项目名称。
2. 项目目标。
3. 背景资料。
4. 成功标准。
5. 约束条件。

### 2.5 自动组队

系统根据 Factory 默认成员生成 ProjectTeam。

MVP 阶段可以先使用规则匹配：

1. 必选岗位直接加入。
2. 可选岗位根据项目目标和能力标签加入。
3. 缺少关键岗位时提示用户补充。

### 2.6 自动拆解任务

Orchestrator 调用管理 Agent，把项目目标拆解成 TaskGraph。

任务必须包含：

1. 标题。
2. 描述。
3. 输入。
4. 预期输出。
5. 负责人角色。
6. 依赖。
7. 验收标准。

### 2.7 执行任务

系统按依赖顺序执行任务。

MVP 阶段只需要支持：

1. 手动触发单个任务执行。
2. Agent Runtime 调用模型生成输出。
3. 保存 AgentRun。
4. 生成 Artifact。

### 2.8 评审产物

Review Agent 或规则评审任务输出。

评审结果：

1. 通过。
2. 需要返工。
3. 等待用户确认。
4. 阻塞。

### 2.9 项目交付

项目完成后生成 Handoff Summary。

包含：

1. 项目目标。
2. 团队成员。
3. 完成任务。
4. 主要产物。
5. 评审结论。
6. 未解决问题。
7. 下一步建议。

## 3. MVP 内置模板

### 3.1 软件开发工厂

用于展示复杂任务拆解和产物交付。

默认岗位：

1. 项目经理。
2. 产品经理。
3. 架构师。
4. 前端工程师。
5. 后端工程师。
6. 测试评审员。

### 3.2 研究分析工厂

用于证明鱼群不是只服务代码开发。

默认岗位：

1. 研究经理。
2. 搜索分析师。
3. 数据整理员。
4. 行业分析师。
5. 报告撰写员。
6. 事实核查员。

## 4. MVP 不做的事情

1. 不做 Agent 公开市场。
2. 不做复杂组织权限。
3. 不做计费系统。
4. 不做完全自动生产部署。
5. 不做跨租户 Agent 共享。
6. 不做复杂可视化流程编辑器。
7. 不做多模型成本优化。
8. 不做企业级审计报表。

## 5. MVP 成功标准

MVP 完成时，用户应该能完成一次端到端演示：

1. 双击打开鱼群桌面应用。
2. 在首屏看到 Agent Operations Dashboard。
3. 创建或选择“软件开发工厂”。
4. 查看默认 AI 员工。
5. 新增一个自定义 Agent 员工。
6. 创建一个项目。
7. 自动组建项目团队。
8. 自动生成任务图。
9. 执行至少一个任务。
10. 查看 Agent 状态实时变化。
11. 查看 Agent 执行日志。
12. 查看生成产物。
13. 完成一次评审。
14. 生成交付摘要。
15. 重启应用后仍能看到历史记录。
